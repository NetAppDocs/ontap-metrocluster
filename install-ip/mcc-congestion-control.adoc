= Configure MetroCluster IP WAN ISL congestion control

:icons: font
:imagesdir: ../media/


[.lead]
Beginning with ONTAP 9.20.1, you can enable WAN Inter-Switch Link (ISL) congestion control in MetroCluster IP configurations so that ISLs running at lower or mixed bandwidths, such as 10Gbps, 25Gbps, or 40Gbps, can be used with platforms that have a MetroCluster IP backend port speed of 100Gbps.

Replication traffic generated by the 100Gbps adapter can overrun ISLs with a lower link speed, causing switch buffer pressure, PAUSE backpressure, packet loss, and potential replication instability. WAN ISL congestion control adaptively throttles replication traffic when ONTAP detects that the ISL bandwidth is insufficient to absorb outbound throughput.

.About this task

* The MetroCluster IP configuration must be running ONTAP 9.20.1 or later.
* WAN ISL congestion control is disabled by default and must be explicitly enabled by the storage administrator on both clusters in the MetroCluster IP configuration. It can be enabled or disabled at any time after you set up the MetroCluster clusters.
* If ISL speeds are uniformly 100Gbps, enabling this feature has no operational effect; throttling is only triggered when backpressure signals are detected.
* WAN ISL congestion control operates automatically after it is enabled. 

== Enable WAN ISL congestion control

.Steps

. Enable WAN ISL congestion control on cluster_A:
+
[source,cli]
metrocluster interconnect congestion-control enable

. Verify that WAN ISL congestion control is enabled:
+
[source,cli]
metrocluster interconnect congestion-control show
+
----
cluster_A::> metrocluster interconnect congestion-control show

Status: enabled
T_auto (MiB/s): 2400
cur_wafl_thrpt (MiB/s): 3100
num_rejected_reqs: 142
suspend_msecs: 12
Driving-signal summary: rx_pause
----
+
NOTE: The output should show that the status is `enabled`.

. Repeat the previous steps on the partner cluster.

== Disable WAN ISL congestion control

.Steps

. Disable WAN ISL congestion control on cluster_A:
+
[source,cli]
metrocluster interconnect congestion-control disable


. Verify that the feature is disabled:
+
[source,cli]
metrocluster interconnect congestion-control show
+
The output should show the status as `disabled`.

. Repeat the previous steps on the partner cluster.

== Monitor WAN ISL congestion control activity

You can use the following command to monitor active throttling behavior and verify that congestion control is functioning as expected:

[source,cli]
metrocluster interconnect congestion-control show

When enabled, the output should be similar to the following example:

----
cluster_A::> metrocluster interconnect congestion-control show

Status: enabled
T_auto (MiB/s): 2400
cur_wafl_thrpt (MiB/s): 3100
num_rejected_reqs: 142
suspend_msecs: 12
Driving-signal summary: rx_pause
----
