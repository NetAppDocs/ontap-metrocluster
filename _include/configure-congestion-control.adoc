Beginning with ONTAP 9.20.1, you can enable WAN Inter-Switch Link (ISL) congestion control in MetroCluster IP configurations so that ISLs running at lower or mixed bandwidths, such as 10Gbps, 25Gbps, or 40Gbps, can be used with platforms that have a MetroCluster IP backend port speed of 100Gbps.

Replication traffic generated by the 100Gbps adapter can overrun ISLs with a lower link speed, causing switch buffer pressure, PAUSE backpressure, packet loss, and potential replication instability. WAN ISL congestion control calculates a ceiling using the ISL bandwidth and node count, writes it as desired state, and the kernel applies it. 

.About this task

* The MetroCluster IP configuration must be running ONTAP 9.20.1 or later.
* WAN ISL congestion control is disabled by default and must be explicitly enabled by the storage administrator. 
* In some configurations, ISL information cannot be obtained automatically when congestion control is enabled. In these scenarios, you must contact NetApp technical support to enable the feature.
* If the topology changes, for example, the count or speed of the ISLs change, or if a new node is added, congestion control must be refreshed to calculate the new ceiling.
* WAN ISL congestion control operates automatically after it is enabled. 
* If you need to modify the calculated ceiling after this feature is enabled, contact NetApp technical support.

== Enable congestion control

Perform the following steps on the local cluster to enable WAN ISL congestion control.

CAUTION: If you have two four-node MetroCluster IP configurations that are connected to the same switches, contact NetApp technical support to enable this feature.

.Steps

. Enable WAN ISL congestion control on cluster_A:
+
[source,cli]
metrocluster interconnect congestion-control enable
+
If the command fails with the following error, you must contact NetApp technical support to enable this feature:
+
`MCC_CC_ISL_INFO_UNAVAILABLE`

. Verify that WAN ISL congestion control is enabled:
+
[source,cli]
metrocluster interconnect congestion-control show
+
----
cluster_A::> metrocluster interconnect congestion-control show

Status: enabled
T_auto (MiB/s): 2400
cur_wafl_thrpt (MiB/s): 3100
num_rejected_reqs: 142
suspend_msecs: 12
Driving-signal summary: rx_pause
----
+
NOTE: The output should show that the status is `enabled`.

== Refresh congestion control

Perform the following steps on the local cluster to refresh WAN ISL congestion control. You must refresh the congestion control configuration whenever the topology changes, such as when the count or speed of the ISLs changes or when a new node is added.

.Steps

. Refresh WAN ISL congestion control on cluster_A:
+
[source,cli]
metrocluster interconnect congestion-control refresh
+
A new ceiling is calculated based on the current network conditions and applied automatically.
+
If the command fails, you must contact NetApp technical support to refresh the WAN ISL congestion control configuration.


== Monitor WAN ISL congestion control activity

You can use the following command to verify that congestion control is functioning as expected:

[source,cli]
metrocluster interconnect congestion-control show

When enabled, the output should be similar to the following example:

----
cluster_A::> metrocluster interconnect congestion-control show

Status: enabled
T_auto (MiB/s): 2400
cur_wafl_thrpt (MiB/s): 3100
num_rejected_reqs: 142
suspend_msecs: 12
Driving-signal summary: rx_pause
----

== Disable congestion control

.Steps

. Disable WAN ISL congestion control on cluster_A:
+
[source,cli]
metrocluster interconnect congestion-control disable


. Verify that the feature is disabled:
+
[source,cli]
metrocluster interconnect congestion-control show
+
The output should show the status as `disabled`.
